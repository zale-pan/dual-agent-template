# 资源从创建到退役

## 创建时先登记

Steward 为本项目选一个明确的外部暂存根，按任务/轮次分层；同一轮的预检、执行和现场复核默认复用同一工作区。第三方工具必须用系统 Temp 时，记录它实际创建的子目录绝对路径。创建前登记预期位置，创建后回填实际路径；工具异常退出也能找到该目录。共享环境、发布候选、用户数据各自登记，分别处置。

| 精确路径 | 类型/所有者 | 任务与轮次 | 活跃消费者及用途 | 解除条件 | 复查时间 | 状态 |
|---|---|---|---|---|---|---|
| <绝对路径> | <如测试 venv / Steward> | <ID> | <实施测试、独立验收> | <两方完成并退出> | <结案时或约定日期> | <在用/待复核/待删/部分删除> |

TTL 是**复查时机**。统一触发点为轮次关闭、消费者退出、已知问题关闭、清理中断后恢复。跨轮等待再填明确日期。只有最后一个消费者释放、保留结论已承接且删除范围获准后才能删。维护者不能以“将来可能有用”续留；须填真实路径、使用方及下次释放事件。

## 精确处置表

| 对象 | 保留到何时、如何处理 |
|---|---|
| 产品源码、正式测试及夹具、工具源码、依赖锁、配置、许可证、维护文档 | 随项目维护。删除旧测试走代码变更和影响分析。测试实际读取的历史 fixtures 先作为共享输入保护，迁至正式测试目录并验证调用者后再退役旧位置。 |
| 批准合同、冻结输入、报告、范围基线、事件/证据索引 | 当前实施、验收和实际消费者使用期间登记。轮次关闭且短总结已承接、解除读取后整份退役。冻结包存续时保持原样。 |
| 测试日志、截图、跟踪输出、模拟 SQLite、一次性诊断代码 | 通过后释放。失败时只留定位仍需的最小输入、输出和断言，指定消费者；修复、接受限制或调查结束时重新裁定。原始输出过期后摘要继续明确“曾失败”。 |
| 仓库副本、预检候选、临时克隆、venv、测试 wheel、构建中间件 | 分别登记实际目录；即使分别叫 repository 和 dispatch-preflight 也要按内容识别。关闭后核对唯一改动、消费者和占用，再列入批准清单。 |
| 安装包及打包脚本 | 区分测试制品、已发布资产、尚未发布的唯一源码。一次试装失败不自动把唯一打包源码变成缓存；移交、已有可验证版本或用户明确放弃后分别处置。 |
| 用户项目、会话数据库、附件、凭据 | 独立于轮次管理，默认排除在运行清理外。用户明确授权相应数据才处理。检查和报告不输出密钥。 |
| Git 对象、引用、工作树、权限恢复数据 | 不按普通 Temp 逻辑批删。先查引用、未提交工作、回滚需求和真实消费者。Git 标记垃圾的临时对象也须精确列名，遇只读、锁或权限拒绝转留存。 |

## 删除与恢复

1. 从登记根枚举实际对象，生成只含本批的清单。每行写规范绝对路径、类别、普通文件数、逻辑字节、盘点时的身份/时间、保留或删除理由。对会影响身份的变化按需记录内容哈希。不跟随链接；统计失败写 unknown。逻辑大小单列，未测物理空间就不报告实际释放量。
2. 排除源码、共享消费者和未解决复现路径。检查候选与受保护路径**双向相交**：删父目录会吞掉受保护子项；受保护父树里的子项也不能单独删。相同目录、不同盘、大小写、邻近同名前缀、.. 和重解析点分别检查。含受保护后代时只列已释放兄弟项。下方片段只判路径关系，不能代替链接和占用检查。
3. Steward 列出精确清单，记录批准绑定的清单版本/摘要。执行前重核规范路径、根边界、引用、进程、链接、数量和字节；内容敏感的候选另核指纹。只处理清单中的对象，不能按通配符重新选一批。新增和变化项留待重新盘点。
4. 逐目标记录 deleted、already_absent、skipped、partial。部分删除记录剩余路径、错误、已知数量或 unknown。普通失败继续独立目标。原根仍存在时，不把其盘点总大小计为已释放。仅限空目录时使用拒绝非空目录的操作。
5. 对所有批准路径重新读回，核对保护项和总结。消失只能证明不存在；区分本次删除和先前已不存在。重试从原清单与实际仍存项的交集开始，只在同一授权和身份仍成立时处理；有新内容、锁、权限或策略拒绝则停止该项。不得绕过策略或更改全盘权限。
6. **轮次裁决**与**存储状态**分开记录。例如验收通过 / 清理部分完成，原因是 11 个只读临时对象仍在。短总结可写“批准 60，删除 59，已不存在 0，部分删除 1，仍存 1”；不能把返回码 0 或开始删除写成清理完成。

以下为 Windows 规范绝对路径的只读关系核对。在实际文件上另须先检查每一级祖先和目标树中的重解析点。候选必须严格位于已登记根内，根自身另行授权。

```powershell
function Test-PathIntersection([string]$a, [string]$b) {
    foreach ($p in @($a, $b)) {
        if (![IO.Path]::IsPathFullyQualified($p)) { throw "需要绝对路径 $p" }
    }
    $a = [IO.Path]::GetFullPath($a).TrimEnd('\') + '\'
    $b = [IO.Path]::GetFullPath($b).TrimEnd('\') + '\'
    $mode = [StringComparison]::OrdinalIgnoreCase
    $a.StartsWith($b, $mode) -or $b.StartsWith($a, $mode)
}
```

## 使用模板自带的清理工具

在目标项目能导入 governance 的环境中使用以下 Python 接口。Steward 提供当前完整引用清单，选用已停写的专用暂存根。候选和引用使用相对该根的路径。每个文件和要移除的目录各列一行；目录仅在已空时移除。先运行预览，将本批清单和用户批准绑定，再执行对应行。

```python
from governance.steward_workflow import apply_cleanup, cleanup_plan

preview = cleanup_plan(root, candidates=relative_paths, referenced_paths=current_refs)
# approved_rows 是用户已批准的 preview["suggestions"] 原始行，保留盘点身份。
batch = apply_cleanup(root, approved=approved_rows, referenced_paths=current_refs)
# 将 batch["remaining"] 保存至本批临时记录。重试前重新读取当前引用。
retry = apply_cleanup(root, approved=batch["remaining"], referenced_paths=refreshed_refs)
```

每个目标返回 deleted、already_absent 或 skipped；部分完成的批次同时返回未完成的原行。已消失或成功移除的目标不会进入剩余清单，即使同名路径重新出现也不会在重试时处理。身份变化、出现新子项、引用未释放或文件仍被占用时，查看对应 reason。上述调用适用于串行、已停写的暂存区；清单身份采用文件系统元数据，不提供并发写隔离或内容哈希证明。

tools.py 没有清理子命令。Steward 按清单核对当前引用、取得具体对象的删除批准，再手工处理或从受控 Python 调用上述函数。轮次的 implementation-baseline.json 在该轮验收、关闭和已知复核消费者全部释放后可列入清单；结案不会自动删除。后续轮次已经开始时，先完成该轮范围对照，避免将期间的退役误认作实施改动。
