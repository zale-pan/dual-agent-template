# 双代理开发模板

适用于一位用户批准范围、一名 Steward 下发及独立验收、一名实施 Agent 写代码的项目。默认采用轻量人工编排。本页用于填写工作单，先完成[轻量 P0](../PROJECT_STARTUP.zh-CN.md)再下发业务任务，无需先建设治理系统。

## 在项目里怎么用

1. **准备**　Steward 读当前任务、相关源码及现有测试。复制 [轮次工作单](轮次工作单.md) 到目标项目当前工作区，填入唯一合同、实施身份、逐路径操作、正反例断言、准确命令及预算。向用户展示实际范围。草案没有写权限。
2. **批准并下发**　记录用户批准的版本和范围，按 [冻结与复用](冻结与复用.md) 冻结必要输入。把工作单位置、指纹、允许写入的位置交给指定 Agent；从实际交付位置读回一致才记“已下发”。收到消息、开始实施各按真实证据记录。下发阶段只做身份和范围核对。
3. **实施**　Agent 先读回工作单和输入，逐项核对指纹；不符即停并指出路径。在授权位置修改，运行指定命令。原始输出先写入已登记的轮次暂存区，完成说明只指向实际结果。发现范围需扩大，先交还 Steward。
4. **验收**　Steward 检查实际新增、修改、删除及未跟踪文件，对照函数边界和输入版本，独立跑影响到的测试。可复用的证据写明源码、命令、依赖、运行条件和覆盖点。影响条件没变的同一回归只跑一次；普通失败继续其他安全独立检查。裁判夹具错误单列，只重跑受影响项。未运行或无法确认写明原因。
5. **结案**　记真实裁决，撤回实施权限，更新当前状态。失败可以结案，修正轮的权限由用户另行批准。已取消或未下发也要写明，不能补造实施记录。
6. **退役**　按 [存储与清理](存储与清理.md) 释放引用、列准删清单并取得对应批准，按路径读回。每个结束轮次长期仅留一份 [轮次总结](轮次总结.md)。有临时保留项时写明位置、消费者及解除条件；后续直接更新这同一份总结的清理状态。

### 给两个 Agent 的开场指令

**Steward**　“先确认本次是准备、下发还是验收。读取当前工作单、实际代码和活跃引用。你负责精确授权、独立验收和关权限。按本模板收尾；对操作失败、未运行和仍保留的材料如实记录。”

**实施 Agent**　“从 Steward 给出的实际位置读取获批工作单，核对任务、轮次、身份和输入指纹。只写指定源码、测试及暂存路径。提交实际差异、执行结果和失败位置；审批、裁决及清理授权由 Steward 管理。”

已有项目接入前先走 [旧项目切换与问题对照](旧项目切换与问题对照.md)。本目录是可复用模板；请将轮次数据放在使用它的项目或该项目登记的暂存区。
