# 独立验收
1. 从实际下发版本核对实施者、输入指纹和授权边界。核对新增、删除、修改及未跟踪路径，检查公共接口、调用者、夹具、依赖和环境的影响。
2. 按已冻结合同运行受影响的正反例与回归。记录命令、退出码、实际覆盖和未运行原因。合同明定全量或影响覆盖需要全量时，在同一最终指纹只跑一次。下发时不演练验收。
3. 其余检查只有在源码、输入、调用关系、命令和环境的复用条件成立时沿用；变化使对应结论失效。遇普通失败继续安全独立检查。来源不可信、安全风险或缺少依赖时停止相关动作。
4. 分别记录产品缺陷、夹具或 Steward 探针错误、环境阻断。受限的离线结果不能证明在线行为。发现合同遗漏，明确补充并获得必要授权后再执行。
5. 写独立裁决，收回权限，保留历史首败及已知限制于轮次短总结。原始材料按实际消费者、批准与读回退役。失败和清理均不自动开启下一轮。

结构化命令运行器直接传递参数数组给子进程。Windows 上命令字符串支持前导调用符 &，单、双引号用于分组，反斜杠按字面保留（包括目录末尾）；需要字面双引号时用单引号包住该参数。POSIX 环境沿用 POSIX 分词。命令不会隐式进入 shell 做变量展开、管道或重定向。

结构化阶段默认限时 300 秒。需要更长或更短的命令应在批准前写入验收计划，例如 `{"command":"python -B -m pytest -p no:cacheprovider -q","timeout_seconds":120}`。接受 1 至 86400 的整数秒数。计时从叶子进程启动后开始；终止和等待退出另有短时限。超时记录 status=timed_out、配置秒数、实际返回码（未确认退出时为 null）、可读输出和 timeout_cleanup。直接进程退出与进程树清理动作分别记录。Windows 针对本次 PID 调用 taskkill /T /F；POSIX 向本次进程组发送 SIGKILL。工具结果不证明脱离进程树的进程已停止。超时阶段证据不合格，不可复用；直接子进程仍未退出或树清理动作未确认时，后续阶段暂停。
