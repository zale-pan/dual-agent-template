# Steward 数据保留与正常清理

暂存区登记、保护路径交集、删除失败与恢复的逐项操作见[存储与清理](lifecycle/存储与清理.md)。历史嵌套包的切换条件见[问题对照](lifecycle/旧项目切换与问题对照.md)。

默认目标：**结束的每轮只留一份简短 Markdown；运行数据用完清理。** 不为归档再复制历史，不以压缩包代替删除，不强制等待 14/30/90 天。磁盘与内存占用分开计量。

## 检查动作与文件寿命：两个独立维度

**继续执行的检查动作**：当前授权/身份、输入身份、实际新增修改删除范围、独立测试、发布读回、权限关闭。这不是永久保存清单；动作完成后只把简短结论记入该轮唯一MD，过程材料消费结束即按规则删除。

**长期保留的文件**：产品源码、正式测试/夹具、仍使用的工具/记录器源码、依赖锁/配置/许可证及必要产品文档；每个结束轮次唯一一份简短MD。正式发布资产和用户聊天/附件按其真实用途管理，不是每轮运行材料。项目可维护一份当前状态/有效授权和摘要定位，不得借项目级JSON、事件表、索引或数据库另存每轮完整审批/命令/报告；关闭历史内容以唯一MD为准，派生索引只存定位/当前流程所需最小状态，不能成为第二份轮次档案。

**暂存而非长期保留**：当前授权包装、冻结包、报告、原始日志、截图、范围清单、快照、临时脚本/夹具、候选/环境、清理过程记录，以及兼容旧程序的事件账本。暂存必须有消费者和解除条件；未解决问题/活跃共享用途释放后删除。每轮“最终只留一份MD”指轮次过程档案，不删除交付源码；还有暂存对象就必须显示“清理未完成”，不能宣称已达到最终状态。

## 事件账本退出条件（过渡，不是永久档案）

以下条件同时满足后的第一次正常收尾，必须将旧事件账本及其副本、索引、快照列入精确清理集合，不得以“项目级保留”继续延期：

1. 所有仍按旧合同执行的活动轮次已关闭权限；包括ForeContract当前P5-T01，不能改其冻结命令或提前豁免。
2. 独立验收证明新流程在旧账本/旧原件不存在时，仍可恢复当前状态、读取所需摘要、验证真实批准/dispatch、拒绝越权和非法状态转换、完成下一轮；同时证明不读旧账本、不自动重建永久事件链。
3. 旧裁决、重要缺陷/失败及已知缺失已承接至各轮唯一MD；当时未证明的事实仍标unknown/unproven，不重跑全历史“洗白”。切换决定只在对应轮次MD和现有当前政策中留简短事实。
4. 所有确实消费账本的恢复/验收/发布/排查任务已释放；无未完成事务和活跃进程。普通历史提及不算消费者。
5. 已批准切换且精确删除目标核对通过（允许根、归属、父子pin、链接/身份）；不因旧的笼统永久保留条文新增许可门槛。

由Steward执行与记录退出；宿主可代执行同样的边界。占用或具体依赖仅阻塞相应目标，写精确路径、消费者、原因、解除条件；最后消费者释放/占用解除/切换验收通过时自动进入下一次收尾核对，不使用无期限“待后续优化”。未达条件明确显示过渡未结束，不能称轻量迁移完成。

退出后：不继续追加旧账本、不复制归档、不迁为永久数据库事件表。当前操作所需回执/事务日志可短期保存到独立裁决和恢复用途结束，然后删除；结论只入本轮MD。新任务直接核当前状态和真实批准/下发绑定，不依赖已删事件前缀。删除后不得自动回退到要求旧原件存在的模式，也不得伪造日志。此处是未来切换/删除合同，本次文档更新不执行删除。

## 1. 文件保留范围（不是检查动作清单）

| 对象 | 保留与清理条件 |
| --- | --- |
| 产品源码、正式测试源码、依赖锁及必要配置 | 持续保留。废弃测试需精确代码授权才能删，不能混入运行数据清理。 |
| 当前轮授权、冻结输入、范围基线、真实提交、独立运行材料 | 独立裁决完成且所有活跃引用解除后，归纳为本轮唯一摘要，再清理原件。实施方自测通过不是删除条件。 |
| 未解决问题的最小复现 | 保留到问题关闭；重要用例纳入正式测试后，清理一次性排查材料。 |
| 报告、日志、截图、非发布构建包 | 通过且无活跃用途即删除；失败材料在排查结束后同样删除。 |
| 候选副本、临时环境、构建中间文件、一次性脚本 | 使用结束、无活跃进程和依赖后回收整个登记工作区。共享环境由最后一个消费者释放。 |
| 正式发布产物、不可重建的必要依赖 | 按发布或依赖用途保留，不把每轮构建当正式发布。 |
| 轮次摘要 | 一轮一个 Markdown：修改、提交/指纹、验证范围与结论、重要缺陷、遗留问题。通常几 KB，不嵌入长日志或完整索引。 |

摘要记录历史结论，不冒充原始证据仍可逐字复验。失败轮保留当时失败结论，注明后续关闭轮次；unknown/not_run 不改为通过。每轮不永久保留多份授权长文、验收报告和包副本。

## 2. 活跃阶段

下发前保存必需完整范围清单（规范路径、类型、长度、SHA256、覆盖/排除项）及实际提供的冻结输入；不无条件复制整库历史，不要求所有对象另存永久副本。原始输出先落盘，再断言和汇总。当前验收所需唯一材料不能放在可能自动回收的系统 Temp。

一次盘点供多项检查复用。失败时保留排查所需首败和最小现场，不永久保留整个失败候选和环境。Implementation Agent 只写 manifest 精确路径及获准 scratch，不获得其他任务或 Steward 审计目录的清理权。Steward 仍不得修改实现或测试。

## 3. 正常收尾清理

1. 完成独立裁决，写本轮唯一摘要，列出遗留问题和仍需保留的精确路径。
2. 核对当前任务、运行中进程、未解决问题、共享依赖、正式发布对材料的引用；父子目录和别名交集都保护，不能只比字符串相等。
3. 解析目标到明确允许根内，拒绝根自身、越界、重解析点、身份漂移、未知归属。目录旧或轮次关闭不能代替用途检查。
4. 按已授权精确清单删除。占用、权限错或新引用只跳过受影响目标，不杀其他进程，不清空当前任务。部分删除如实记录，可从未完成目标恢复。
5. 核对实际删除状态及受保护源码、当前输入未变。把范围、理由、结果、空间口径、耗时写回所属轮次唯一MD；跨轮批次不再永久保留独立清理报告。过程清单消费结束删除，不为删除再做全量备份。

清理属于正常收尾，已有授权不重复询问。正式测试通过后，报告、日志、截图和临时环境也适用；测试源码保留。

## 4. 关闭历史与当前输入分开

新轻量流程以现有项目状态和唯一轮次摘要承接关闭历史，不要求永久保存原始日志，也不要求新建退休检查点平台。当前授权、输入、实际范围和仍用于结果复用的原件严格验证；关闭摘要不是可重放原始证据。旧失败/unknown/历史缺失仍保留，不补造日志。

## 5. 旧项目一次切换，新项目直接采用

旧检查器仍依赖原件时，先用最小适配合同解除该依赖并独立验证；在现有项目政策/状态中记录真实批准、版本、关闭轮身份/原裁决/摘要绑定和仍活跃用途。无需每个文件建永久退休台账，不重验全部历史来生成新的“完整历史证明”。已知缺失明确承接限制。切换前不删硬依赖原件，切换后不把退休原件重新引入下一轮门禁。

新项目直接采用轻量生命周期，宿主提供或Steward手动执行；不强制先完成P0治理平台开发。当前项目、旧冻结包和权限不会因复制模板自动改变。未登记的当前输入缺失或摘要身份/绑定损坏仍拒绝；不能全局ignore-missing。

## 6. 编排接入合同：登记、释放、清理与检查（2026-11-12）

本节把已有保留原则落实为编排输入和验收要求；不是已实现的自动化。复用现有项目资源登记和轮次摘要，不另造每轮永久台账。实现位置可在宿主编排器；无需每个业务项目重复开发清理平台。

### 6.1 创建时登记用途与释放条件

每个运行工作区或共享对象至少登记：规范绝对路径/对象ID、允许根、所属task/round、创建者、用途、当前消费者、释放条件、状态、保留原因及下次复核触发点。按工作区或共享对象登记，不给每条日志另建永久记录。

- active：当前执行、独立验收或排查仍在消费。
- pinned：明确消费者仍需原件；必须说明具体用途和解除条件，不能仅填“审计需要”。
- retired：独立裁决完成、摘要已承接历史结论、全部活跃消费者释放、关闭状态及摘要已由Steward接受；允许进入精确删除集合。
- 删除结果另记 cleaned、partial 或 blocked，不能把标记 retired 当作已经删除。

活跃引用是执行/验证/恢复确实需要原字节的依赖；普通历史文字提及不自动构成 pin。检查器仍要求原件存在时，登记为兼容依赖和待适配项；未经验证不得把硬依赖当成普通文字引用。共享对象由最后一个消费者释放；产品源码、正式测试、正式发布产物及必要不可重建依赖不随轮次回收。

### 6.2 收尾顺序与完成条件

编排顺序固定为：独立裁决和权限关闭 → 一份轮次摘要 → 重新核对并释放活跃引用 → 确认关闭状态和摘要绑定 → 精确清理 → 核对删除结果和当前项目可读性。

摘要包含修改与指纹、验证范围/结论、重要缺陷及遗留问题；失败和unknown不改成通过。当前仍用于复用检查的原件在消费者释放前保留。无绑定scratch不建立历史检查点。

裁决结果与清理结果分开记录：业务verified不等于cleanup完成；清理受阻不重跑已通过业务。无活跃用途的报告、日志、截图、非发布构建、一次性脚本、候选及临时环境都适用，失败轮在排查结束后同样适用。部分失败继续安全独立目标；占用解除、问题关闭或最后消费者释放时重试受影响目标。

收尾必须给出 cleaned / partial / blocked，列出剩余精确路径、原因和下次触发点；不得只写“以后清理”。小型结果写入本轮唯一摘要，当前项目状态按轮更新；不为清理复制原件、完整目录或生成另一套永久长报告。已有精确范围授权不重复询问，不能以模板条文替代未获得的删除授权。

### 6.3 检查器与历史结果的边界

轻量模式只检查当前任务、实际消费者和所需摘要。旧项目已验证切换后，已关闭原件缺失不再报错；当前包缺件、错身份、损坏摘要/关闭状态绑定仍拒绝。政策不能由实施方报告或命令行临时开关绕过。

关闭摘要保存当时裁决，不证明已删除原日志仍存在，不证明新源码通过旧测试。未来任务需要新证据时按影响和冻结计划执行。不要让已退休历史日志重新进入新轮完整输入清单。

### 6.4 集成前必须验证的场景

| ID | 输入与应有结果 |
| --- | --- |
| LIFE-01 | 关闭轮次、摘要和已接受关闭状态：删除报告/日志后检查通过并标retired；正式源码和测试不变。 |
| LIFE-02 | 同一对象有两个消费者：释放一个不得删除，最后一个释放后才可清理；普通历史文字引用不无限续期。 |
| LIFE-03 | 当前轮输入或未解决复现被误标过期：删除前拒绝，目标保持原字节。 |
| LIFE-04 | 当前输入缺失、摘要/关闭状态绑定被改、接受绑定伪造：分别失败，不能变成合法退休。 |
| LIFE-05 | 根外路径、父子pin交集、junction/别名、占用或中断：拒绝/跳过受影响项；可安全目标继续；恢复重入不误删。 |
| LIFE-06 | 正常验收→摘要→释放→清理→下一轮：退出过渡后移除旧事件账本，下一轮仍可运行；无历史全量复制，不新增第二份永久轮次报告，不重跑未变业务；清理结果和剩余pin可读。 |

冻结前将这些场景绑定到实际断言源码、夹具、命令和精确实现范围。只有运行并独立通过后才标记verified；目前本模板只提供合同，不提供已验证执行器。目标项目明确记录 configured / implemented / exercised / verified，未测为unknown。

## 8. 逐类文件处置表（2026-11-12 明确要求）

本表是具体保留合同。不能用“保留必要证据”“按需清理”替代下列处置。这里的“轮次结束”指独立裁决已完成；失败轮还须结束排查。删除前逐项确认：本轮唯一摘要已写入，当前执行/验收/未解决问题/共享消费者均不再需要该对象；被旧检查器绑定的原件还须完成已独立验证的流程切换。任一条件不满足，只保留受影响的精确对象，并在摘要写明消费者、阻止删除的具体原因和解除触发点。不得笼统保留整个任务目录。

| --- | --- | --- |

| 候选目录、临时安装环境、venv、构建中间文件、非发布wheel/sdist | 当前执行、验收或共享消费者使用的工作区 | 最后消费者释放且无活跃进程后删除登记工作区；不得保留整套失败候选作永久备份。 |
| 正式发布产物、不可重建必要依赖、正常Git工作副本 | 按发布、依赖或后续开发用途使用的对象 | 按该用途保留；普通轮次构建不自动算正式发布，上传验证用的额外副本仍按临时材料处理。 |
| 当前项目状态/有效授权、活动资源登记 | 当前执行所需字段与摘要定位 | 维护当前值；释放后删除资源条目，不累计每轮完整过程档案。 |
| 旧事件账本/副本/事件快照 | 仅尚未切换的旧合同消费者 | 按本页五项退出条件，满足后首次正常收尾清理；不复制、压缩归档或迁入永久事件表。 |
| 清理计划、临时扫描清单、删除结果及上传审计材料 | 当前清理/上传核对所需的过程文件 | 操作完成后只在对应简短摘要记范围、结果、剩余项和耗时；删除过程日志、扫描清单及重复报告。仍受检查器绑定的对象按精确兼容依赖暂留。 |

执行结果必须逐类给出：已删除路径/数量、仍保留的精确路径及原因、下次解除条件。没有执行删除时只能报告“处置规则已配置，实际清理未执行”。没有验证检查器兼容时只能报告“轻量切换未验证”，不能声称已实现自动清理或结束轮次已只剩MD。
