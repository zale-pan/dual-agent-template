# P0-T01: Governance checks bootstrap

## Control

- Status: `draft`
- Owner role: `implementation_agent`
- Goal references: `G-GOV-001`
- Acceptance references: `G-GOV-001-AC01`, `G-GOV-001-AC02`
- Manifest: `tasks/active/P0-T01.task.json`
- Consultation: `tasks/consultations/P0-T01.zh-CN.md`

## Objective

Implement or adapt read-only project-consistency and changed-path scope checks, including
immutable package and JSON-derived-view validation, so the Task Steward can independently
detect ledger drift, changed inputs, stale views, and unauthorized implementation writes.

## Required behavior

### REQ-01: Project consistency check

Validate resolvable Goal/AC/task references, dependency ordering, current-task alignment,
evidence references, round-manifest hashes, governance-event sequence/hash-chain/state
agreement, and forbidden premature status transitions without mutating files.

### REQ-02: Scope check

Given a role, approved task manifest, and explicit changed paths, reject paths outside the
exact task authorization or inside globally forbidden/protected scopes. Reject traversal,
normalization ambiguity, and missing manifest context.

### REQ-03: Package and review-view integration

Adapt the supplied package builder/verifier and JSON-to-Markdown renderer to the target
repository. Project and scope checks must reject missing, extra, tampered, or unauthorized
package members; project check must reject stale or hand-edited generated views. The
read-only modes must not write, and no business task may use the P0 bootstrap exception.

### REQ-04: Positive and negative tests

Cover valid state, broken references, pointer drift, missing evidence, changed round input,
broken/reordered/tampered event lines, authorized paths, unauthorized paths, protected
paths, traversal attempts, package tampering, stale views, and forbidden output paths.
Failures must be actionable and must not expose secrets or read protected content
unnecessarily.

## Authorized write scope

Only the exact paths listed in `tasks/active/P0-T01.task.json`. Replace the placeholder
paths during consultation to match the target repository. Stop if another path is needed.
Before editing, verify every raw-byte SHA-256 in the Task-Steward-owned round manifest.
Do not create or modify provenance manifests or governance events.

## Out of scope

- Business feature implementation.
- Editing goals, ledgers, task documents, evidence, or protected surfaces.
- Claiming operating-system isolation from repository-level checks.

## Acceptance

The Task Steward independently runs all positive and negative drills, confirms the checks
are read-only, records limitations, and alone decides whether the task is `verified`.
The Implementation Agent writes only the authorized completion report and includes the
verified round-manifest digest as an implementation claim.

## REQ-05: Temporal consultation witnesses

Implement CONSULTATION_WITNESS_RULES.md in full: latest eligible earlier task-specific
position determines the first predecessor; same-position conflict rejects; tracked event
state cannot be reset by later snapshots. Preserve defaults, evidence/hash/transition
validation, read-only behavior and historical-event causality. Test the complete positive
and negative matrix with integrated external event fixtures and independent reruns.

## REQ-06: Round identity, recovery and publication

Compare explicit task/round identities across live/frozen task, route, package and report.
Validate every historical dispatch but reconcile the live dispatch only for its current
round. Stale IDs, wrong report paths/digests and missing actual dispatch must reject.
Cover failed-round correction, approved-undispatched replacement and the genuine
pre-report missing condition. Preserve active/pinned inputs; retire closed-round originals only under REQ-07. Verify the complete
fresh-project lifecycle before business approval, rather than isolated helper examples.

## REQ-07: Evidence retirement and normal cleanup

Implement docs/STEWARD_STORAGE_VALIDATION.zh-CN.md. One short Markdown per independently closed round is the durable human record. Use one compact project checkpoint to retire unpinned packages/reports/runtime outputs without copying all history. Keep source, formal tests, active authorization/inputs and unresolved reproductions. A submitted report alone cannot trigger retirement.

Verify accepted checkpoint/summary identity, original validated prefix and boundary states before deleting bound originals. Keep known historical proof gaps explicit. Authorized retired references pass with a retired classification; arbitrary missing/tampered inputs, forged/future checkpoints, changed prefix/state and current-round retirement fail. Verify parent/child and alias pins, shared dependencies, root/traversal/reparse protection, partial deletion and safe resume, plus the complete close-summary-retire-check-next-dispatch lifecycle. Current package checks remain strict. No global ignore-missing and no automatic deletion in read-only validation.

These capabilities are not implemented by the copied template. Replace all exact path/command placeholders during consultation, freeze the executable positive/negative tests before approval, then independently verify both project and cold-template behavior. Steward does not implement the checks.
