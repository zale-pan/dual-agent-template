# P0-T01：治理检查器启用

> 中文人工审阅版。正式执行依据为英文任务书、任务 manifest 和状态账本。

## 目标

由 Implementation Agent 实现或适配只读的项目一致性检查、变更范围检查、
不可变任务包校验和 JSON 派生审阅页检查，使 Task Steward 能独立发现引用漂移、
证据缺失、输入篡改、审阅页过期和未授权路径。Task Steward 不修改检查器代码。

## 待商讨范围

- 根据目标仓库确定检查器与测试的精确路径；
- 明确账本、任务指针、引用、证据、round 输入哈希和事件哈希链检查规则；
- 明确允许/禁止路径、路径规范化和目录穿越的拒绝规则；
- 将模板包的 package builder/verifier、view renderer 与目标项目检查器接入，
  授权它们及测试所需的精确文件路径；
- 约定输入被改写、事件断链/重排/篡改等负向演练，以及全量回归、lint 和构建命令；
- 明确仓库检查不等于操作系统沙箱。

当前状态为 `draft`。只有用户商讨结论为 `agreed` 后，Task Steward 才可定稿精确
授权并创建真实 round；模板文件本身不授予写权限。

## 强制时间与轮次验收

英文 REQ-05/REQ-06 新增完整首个商讨时间见证与轮次门禁。必须实现
CONSULTATION_WITNESS_RULES.md：不同时点演进通过，同一最新位置冲突、旧声明、
未来/同事件/缺失/篡改证据、重复同意和非法迁移拒绝。首次事件后以真实迁移链为准。
同时核对所有显式 task_id/round_id、报告路径与下发哈希，验证失败新轮和未下发重包。
新项目完整生命周期、正负向演练和独立证据全部通过后才可启用。
